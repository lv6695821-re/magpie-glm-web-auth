# GLM 智谱清言 (Web) — Magpie 非官方插件

**非官方声明**：本项目是 [Magpie](https://github.com/yetone/magpie) 的第三方供应商插件，**不是智谱（Zhipu AI）官方产品**，也未收录进 [magpie-community/plugins](https://github.com/magpie-community/plugins) 官方市场。实现遵循该社区仓库的插件规范，结构对齐其包约定（同类参考：magpie-deepseek-web-auth）。

它把你在浏览器里**已登录的 [chatglm.cn](https://chatglm.cn)（智谱清言）账号**接入 Magpie：读取网页会话令牌，按网页端自己的协议（签名请求 + 快照式 SSE 流）发起对话——不消耗智谱开放平台 API 额度，走的是网页账号本身的额度。

包名 **`magpie-glm-web-auth`**，供应商 id **`glm-web`**。

| 模型 | 思考 | 说明 |
|---|---|---|
| `glm-5.3` | 开 | 网页端当前旗舰（chat_mode: zero） |
| `glm-5.2` | 开 | 上一代旗舰 |
| `glm-4.7-flash` | 关 | 快速版 |
| `glm-5.3-search` | 开 | 同 `glm-5.3`，强制联网搜索 |
| `glm-4.7-flash-search` | 关 | 同 flash，强制联网搜索 |

网页端实际只有一个主聊天助手（assistant_id），模型差异由 `meta_data.chat_mode` 控制——`zero` 为思考模式，空串为普通模式。联网搜索默认跟随网页端开关（默认开），单次请求在请求体传 `"search_enabled": false` 可关闭（`-search` 变体不可关）。

## 登录

两种方式（`magpie plugin login glm-web` 或在插件页点击登录）：

- **浏览器登录（推荐）**：插件会**打开一个独立的浏览器窗口**（复用本机已装的 Edge / Chrome / Brave 二进制，优先 Edge），指向 chatglm.cn——你在那个窗口里正常登录（扫码或密码），插件在后台监听会话，拿到网页写入的 `chatglm_refresh_token` 后**自动完成登录并关闭窗口**。要点：
  - **不碰你正在使用的浏览器**：不读取运行中浏览器的 Cookie 文件（它们被独占锁定，且新版 Chrome/Edge 的 Cookie 是 App-Bound 加密、外部无法解），登录态与你的日常浏览器互不干扰。
  - **独立 profile 常驻** `~/.magpie-glm-web-auth/`：上一次登录的会话保存在插件自己的 profile 里；**再次登录时若该会话仍有效，直接静默复用，不再弹窗**。
  - 登录窗口最长等待 5 分钟（扫码足够）；取消或超时会明确报错。
  - 零依赖实现：直接走浏览器自身的 DevTools 协议（CDP over WebSocket），无需安装 Playwright 或任何浏览器驱动。
- **粘贴令牌**：不想开窗口时，在已登录的 chatglm.cn 标签页按 F12，从 **Application → Cookies → `chatglm_refresh_token`** 复制它的值粘贴给插件；也可以在控制台执行：

  ```js
  document.cookie.match(/chatglm_refresh_token=([^;]+)/)?.[1]
  // 若为 undefined（HttpOnly 的情况），去 Application → Cookies 面板手动复制
  ```

令牌长期有效（网页端 Cookie 有效期约 180 天）；退出登录或改密会使它失效，届时重新登录网页再登录一次插件即可。智谱会在刷新时轮换 refresh_token，本插件按网页端自身流程处理。

## 连续对话如何工作

一个 Magpie 会话对应 **一个** chatglm.cn 会话（conversation）：

- 插件通过 `chat.headers` 钩子拿到 agent 的会话 id，把同一会话的后续轮次**接续**到同一个网页会话里：每轮只发送新增的用户消息——与网页端行为一致，历史不重发。
- 标题请求（magpie 生成会话标题的内置提示词）不属于对话内容：它在**一次性临时会话**里应答，标题返回后**即删除**该临时会话，以避免与对话无关的会话残留在账号的会话列表中。
- 会话失效（被删除、过期）自动开新会话并携带全量标注历史重试一次，上下文不丢。
- 网页端"同账号同时只能有一路生成"的限制按网页端自身行为处理：忙（10061）时等待数秒后重试，最多 3 次。

## 思考与联网

- **思考**：`glm-5.3` / `glm-5.2` / `*-search` 变体走思考模式（`chat_mode: "zero"`），思考内容以 `reasoning_content` 流出，不混入正文；`glm-4.7-flash` 走普通模式。单次请求传 `"reasoning_effort": "low"` 可临时关思考。
- **联网搜索**：默认跟随网页端开关（开）；请求体传 `"search_enabled": false` 可对单次请求关闭。搜索过程中的检索摘要（标题与链接）以 `reasoning_content` 形式流出。
- 网页端的代码运行器输出、检索结果等过程性内容同样归入 `reasoning_content`。

## 工具调用

网页端协议本身没有 `tools` 字段，插件的工具调用是**提示词层面的桥接**：

- 声明了 `tools` 的请求，其提示词会先注入一段调用协议，教模型用网页端自家的 DSML 标记（`<|DSML|tool_calls>` / `<|DSML|invoke>` / `<|DSML|parameter>`）发起调用；
- 回复里的 DSML 块被解析为 OpenAI `tool_calls`（每个调用一条完整 delta），该轮以 `finish_reason: "tool_calls"` 结束；下一轮的工具结果按 `Tool result (name): …` 回填进提示词；
- **容错解析**：模型实际输出的 DSML 常有变形（缺竖线、`toolcalls` 连写、纯 XML 风格、CDATA 缺失、代码块包裹）——解析器逐一容忍；解析失败的块折入 `reasoning_content`，永不混进正文；
- 代价在模型侧：调用质量取决于模型对协议的遵守程度；`tool_choice: "none"` 或无 `tools` 的请求完全不走这套机制。

## 附件

首版只做文本：消息里的图片/文件分片会被忽略（Magpie 网关本身也只透传图片分片）。文档内容请直接粘贴进对话。

## 限制

- 同一账号同时只能有一路生成（网页端自身限制），插件按网页端行为等待重试。
- 网页端没有可读的额度接口，用量卡片不显示窗口。
- 附件（图片/文件）暂不支持，计划后续按网页端 `file_upload` 协议接入。
- **Agent 场景实测效果有限。** 经实测，把网页端模型接入 agent（工具调用场景）后，模型经常不肯干活——倾向于只给出文字回答而不发起工具调用，疑似网页端对非网页使用场景做了限制。本插件的 DSML 工具桥接（见「[工具调用](#工具调用)」）能解析模型输出的调用块，但无法强迫模型发起调用；依赖 agent 自主干活的场景请评估后使用，或改用智谱开放平台官方 API。
- 法律、合规与账号相关风险，见顶部「[免责声明](#免责声明)」与「[合规风险说明](#合规风险说明)」——安装或使用前请完整阅读。

## 开发

```sh
npm test                     # 全部测试（fake 假服务器，不触网）
npm run check                # 以宿主方式加载插件并校验钩子
```

结构：运行时源码在 `src/`——`index.mjs`（入口：导出 `server` 与测试用的 `_internal`）、`config.mjs`（供应商 id、模型与页面常量）、`api.mjs`（网页 API：请求头、签名、应答信封、会话删除、标题请求识别）、`browser-login.mjs`（受控浏览器登录：启动本机 Edge/Chrome 的独立 profile，CDP 监听会话 Cookie）、`browser-token.mjs`（浏览器 Cookie 库/Local Storage 的读取与解密，供静默复用）、`sqlite.mjs`（零依赖的只读 SQLite 读取器，供 Cookies 库扫描）、`token.mjs`（access_token 生命周期：刷新、缓存、并发合并）、`stream.mjs`（SSE 快照流读取与 DSML 工具块解析）、`openai.mjs`（OpenAI 兼容分片与消息扁平化）、`toolcall.mjs`（工具调用协议与 DSML 渲染）、`turn.mjs`（单轮补全与忙重试）、`plugin.mjs`（`server` 钩子组装）；测试在 `test/`，假服务器为 `test/fake.mjs`。
